# Macnman Firmware Repository

This repo manages the folder structure and firmware binaries for Macnman devices.
Each device folder holds its firmware image (`.bin`) and product photo (`.png`), and
`LoRaWAN/sensors_v1.json` is the single manifest that describes every device so the OTA /
provisioning tool can locate the right file.

---

## Folder Structure

```

├── .md                                  <- this file
└── LoRaWAN/
    ├── sensors_v1.json                  the only manifest
    │

    │   ├── MacSync-LBS-NS/
    │   │   ├── MacSync_LBS_NS_X1.bin

    │   ├── MacSync-LBS-ToF/
    │   │   ├── MacSync-LBS-ToF-X1.bin
    │   │   └── MacSync-LBS-ToF-X1.png
    │   └── MacSync-LPS-ToF/
    │       ├── MacSync-LPS-ToF-X1.bin
    │       └── MacSync-LPS-ToF-X1.png
    │
    ├── dataloggers/                     multi-channel logging devices
    │   └── MacSync-LBD-STD/
    │       ├── MacSync-LBD-STD-X1.bin
    │       └── MacSync-LBD-STD-X1.png
    │
    ├── LoRa/                            raw LoRa (point-to-point) devices
    │   ├── MacSync_MBS_DRS/
    │   │   ├── MacSync_MBS_DRS_X1.bin
    │   │   └── MacSync_MBS_DRS_X1.png
    │   └── MacTalk_LT1/                 (empty)
    │
    └── controllers/                     reserved — folder kept, no firmware
        └── MacSet-LPO/                  (empty)
```

Empty folders contain a `.gitkeep` file, because git cannot track a truly empty directory.
Delete the `.gitkeep` when real firmware is added to that folder.

## Naming Convention

```
MacSync - L B S - TH - X1
   |      | | |    |    |
   |      | | |    |    +-- hardware revision (X1, X2, ...)
   |      | | |    +------- measurement / payload (TH, NS, ToF, DRS, STD, PO)
   |      | | +------------ S = Sensor, D = Datalogger
   |      | +-------------- B = Battery powered, P = externally Powered
   |      +---------------- L = LoRaWAN, M = raw LoRa (point-to-point)
   +----------------------- product family
```

Example of the raw-LoRa radio letter: `MacSync_MBS_DRS_X1` — **M**BS = raw LoRa, Battery
powered, Sensor.

Product families:

| Prefix | Meaning |
|---|---|
| `MacSync` | Sensor / datalogger nodes that report data |
| `MacSet` | Controllers that drive outputs |
| `MacTalk` | Raw LoRa point-to-point devices |

Folder names use hyphens (`MacSync-LBS-TH`). File and JSON key names use either hyphens or
underscores depending on when they were added — see the mismatch note below.

Interface types used in the manifest: **I2C**, **RS485**, **Analog**.

## Manifest — `LoRaWAN/sensors_v1.json`

Supports multiple firmware versions per device under a `versions` array.

```json
"MacSync_LBD_STD_X1": {
  "devicetype": "datalogger",
  "protocol": "LoRaWAN",
  "sensorName": "MacSync_LBD_STD_X1",
  "type": "RS485",
  "versions": [
    {
      "application": "V1.0.0",
      "binpath": "LoRaWAN/dataloggers/MacSync-LBD-STD/MacSync-LBD-STD-X1.bin",
      "photopath": "LoRaWAN/dataloggers/MacSync-LBD-STD/MacSync-LBD-STD-X1.png"
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `devicetype` | `node` for sensors, `datalogger` for loggers |
| `protocol` | Radio protocol — `LoRaWAN` or `LoRa` (point-to-point) |
| `sensorName` | Display name (currently same as the key) |
| `type` | Hardware interface — `I2C`, `RS485`, `Analog`, `Digital` |
| `versions[].application` | Firmware version string, e.g. `V1.0.0` |
| `versions[].binpath` | Repo-relative path to the `.bin` |
| `versions[].photopath` | Repo-relative path to the `.png` |

Entries: `MacSync_LBS_TH_X1`, `MacSync_LBS_NS_X1`, `MacSync_LPS_ToF_X1`,
`MacSync_LBS_ToF_X1`, `MacSync_LBD_STD_X1`, `MacSync_MBS_DRS_X1`. Every path in the
manifest resolves to a real file.

### Use with BLE OTA

The firmware host app fetches this manifest, shows the user the device list, then downloads
`binpath` for the chosen version and pushes it to the device over BLE DFU. For that flow:

- `binpath` must be the **raw application image** the bootloader expects — a plain `.bin`,
  not a `.hex`, `.zip` or signed package. If your BLE stack needs a packaged image, add it
  alongside and point `binpath` at the package instead.
- `protocol` describes the device's **data radio** (`LoRa` / `LoRaWAN`), not the OTA
  transport. BLE is the update channel for every device here.
- `application` is what the app compares against the version reported by the device to
  decide whether an update is offered — keep it accurate and bump it on every release.

> The old flat-format `sensors.json` (one version per device, no `versions` array) was
> removed. `sensors_v1.json` is now the only manifest — any tool still reading
> `sensors.json` must be pointed at it.

## Adding New Firmware

1. Create `LoRaWAN/<category>/<Device-Folder>/` — category is `sensors`, `dataloggers`,
   `controllers` or `LoRa`.
2. Drop in `<Device-Name>.bin` and `<Device-Name>.png`.
3. Add an entry to `LoRaWAN/sensors_v1.json` using the schema above. For a new version of
   an existing device, append to that device's `versions` array instead of adding a new key.
4. Check that `binpath` and `photopath` match the real files exactly — paths are
   case-sensitive on the server and start at the repo root (`LoRaWAN/...`).
5. If the folder previously held only a `.gitkeep`, delete that placeholder.
6. Commit both the binaries and the manifest change together.

## Known Issues

**Hyphen vs. underscore inconsistency.** Folder names always use hyphens, but file names
are mixed: `MacSync-LBS-TH/MacSync_LBS_TH_X1.bin` uses underscores while
`MacSync-LBS-ToF/MacSync-LBS-ToF-X1.bin` uses hyphens, and JSON keys use underscores while
folders use hyphens. Not a bug today because every path is written out explicitly, but it
will break any code that derives a path from a device name.
